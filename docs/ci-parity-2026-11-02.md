# CI ↔ gate parity, 2026-11-02

Does `.github/workflows/ci.yml` prove the same things `bin/gate` proves? It did not. This pass
compares them step by step, lists every divergence, fixes the cheap ones, and states exactly
what still needs a runner to confirm.

**Verdict before this pass:** the two disagreed in both directions. CI ran four checks the gate
never ran, the gate ran one check CI never ran, and CI's browser step depended on the runner's
CPU count. A developer could pass `bin/gate` locally and fail on a PR — and, worse, CI could be
green on a tree the gate would have called FAIL.

**Verdict after:** CI calls `bin/gate --ci`. One definition of "verified", with one announced
exception (the Convex auth boundary) that a runner cannot supply.

`package.json` `verify` is `check && lint && test && build` — that is 10 of CI's checks in one
script, and it is why the old workflow looked complete. It is not a superset of the gate: it
lacks the bridge test, the dev-server smoke (separate script), and the Node smoke (separate
step), and its `test` step cannot distinguish "441 passed" from "438 passed, 3 skipped".

## 2. Drift found

### 2a. Steps the gate ran, CI did not

1. **Bridge contract test** — `node --test bridge/terminal-bridge.test.mjs`. Spawns the real
   bridge process and exercises `401`, `exec`, `fs/write`+`fs/read`, an out-of-root write, a
   body over 64 KB, unknown path, foreign `Origin` (8 tests). `bun run verify` never touches it,
   `bridge/` is not in the vitest `include` globs, and `tests/` is only `*.e2e.ts`. So the
   bridge's HTTP contract ran on exactly one machine: the author's.
2. **Skip accounting** — the gate parses `--reporter=verbose` and exits 2 on any skip. CI ran
   `bun run test` with the default reporter, so the three Convex auth tests skipped themselves
   on every run and CI reported success. This is precisely the failure mode the repo already
   hit once: a step that silently degrades to a skip.

### 2b. Steps CI ran, the gate did not

1. **`scripts/check-svelte5.mjs`** — rejects `$:`, `export let`, `on:event`,
   `createEventDispatcher`, `<slot>` under `src/` and `slices/`. CI enforced it through
   `lint:svelte5`; `bin/gate` never called it.
2. **`scripts/version.mjs --check`** — `package.json` and `version.json` must agree. CI enforced
   it; a version bump that updated one file passed the gate.
3. **`bun scripts/assets.ts check`** — generated icon manifest hashes. CI enforced it; a stale
   `static/brand/manifest.json` passed the gate.
4. **`bun run test:dev`** — `playwright.dev.config.ts`, which boots `vite dev` rather than
   `vite preview` and greps four smoke tests. The gate only ever proved the preview build.
5. **Node-adapter build + `scripts/smoke-node.mjs`** — `DEPLOY_TARGET=node bun run build` then a
   real server on `127.0.0.1:4199`: routes, the disabled-capability `/api/ai/config` body, the
   `no-store` header, the client entry asset, `/nope` → 404. The gate built for the default
   (`vercel`) adapter only, so the Node adapter's output was proven nowhere locally.
6. **`secret-scan.sh` was absent from both.** It exists, `docs/README.md` says it "must exit 0
   before any commit", and no automated step ran it. Now in the gate.

### 2c. Skips and machine-tuned values

- **Playwright worker count.** `bin/gate` passed `--workers=2`; CI passed nothing, so the count
  followed `os.cpus()`. Measured here on 16 cores: default count tears down `webServer` while
  workers are still navigating and 77 tests fail `ERR_CONNECTION_REFUSED`; `--workers=2` passes;
  `--workers=1` passes, slower. GitHub's `ubuntu-latest` is 4 vCPU, so the runner would land on
  a _different_ number again — 4, which this repo has never measured. Deterministic beats lucky:
  `workers` now lives in `playwright.config.ts` and both callers inherit it.
- **`webServer.timeout: 300_000`.** Tuned against a warm laptop. Kept, but now
  `PLAYWRIGHT_WEBSERVER_TIMEOUT`-overridable, because a cold runner is slower than this host and
  a runner-specific failure would look like a code regression.
- **`vitest testTimeout: 30_000`.** Raised from 5 s because the typed-ESLint specs boot a full
  project service; unrelated to the machine, left alone.
- **Playwright `--grep` in the dev config.** `playwright.dev.config.ts` selects four tests by
  title. If a title is renamed, the grep matches nothing, zero tests run, and Playwright exits
  **0**. Neither CI nor the old gate would have noticed. The gate now asserts the dev suite's
  test count and reports UNPROVEN on zero.
- **Playwright declared skips.** 62 of 426 tests skip at non-desktop viewports
  (`test.skip(project.name !== 'desktop', reason)` in `tests/surfaces.e2e.ts`). Honest, because
  they state a reason. This is exactly the distinction the gate now enforces: a skip **with** a
  reason is printed and allowed; a skip **without** one is UNPROVEN, and so is a suite that ran
  zero tests. Verified against real reports: the `narrow-mobile` skip carries
  `"one pass; the window markup is width-independent"`, and the JSON reducer recovers it.

### 2d. Environment drift

| Claim                           | Where                                              | Value                     | Consistent?                                                                             |
| ------------------------------- | -------------------------------------------------- | ------------------------- | --------------------------------------------------------------------------------------- |

| Node types                      | `devDependencies` `@types/node`                    | `^22`                     | consistent with 22/24                                                                   |

What is actually _required_: `scripts/install.mjs` enforces `MIN_NODE = 22` and warns beyond
`{22, 24}`; the Convex push refuses Node 26 (`DeploymentNotConfiguredForNodeActions`); the
Vercel runtime is pinned to `nodejs22.x`; the Dockerfile pins `node:22`. Nothing in the repo
checks `engines` at runtime — `.npmrc` has `engine-strict=true`, which only applies to npm/bun
installs, not to `npx`/`node`.

**What CI would do with the Convex push: it never attempts one, and that is correct.** With
`setup-node` reading `.node-version`, the runner is on 22.23.2, inside what Convex accepts. The
workflow does not run `convex dev` because it has no deployment and no credentials — it just
reports the three auth tests as an accepted hole. Worth stating plainly: if someone later adds a
push step, Node 22 is already correct there, and `.node-version` is the single input to change.

**Local↔CI asymmetry that remains:** this host runs Node 26, CI runs 22. `npx vitest run` and the
gate pass on 26; the Convex push does not. That is a real local hazard, documented in
`docs/convex-local-setup.md`, and it is not something a workflow can fix — but it means "passes
on CI" and "can push Convex locally" are proven on different Node majors.

### 2e. Secrets

- **CI needs no secret for what it runs.** Auth, AI and MCP are disabled in every test config
  (`AUTH_ENABLED=false`, `AI_ENABLED=false`, `MCP_*_ENABLED=false`, `PUBLIC_CONVEX_URL=''`), so
  no provider credential is exercised anywhere.
- **The one secret-shaped hole is Convex.** Without a deployment the three anonymous-refusal
  tests skip. The old workflow let that pass silently inside `bun run verify`. That is the
  failure this repo already hit: four security tests, permanently skipped behind a dead port,
  green forever.
- **What CI now does instead of skipping quietly:** `bin/gate --ci` prints the skip reasons,
  emits `::warning title=gate: vitest UNPROVEN in CI (Convex auth boundary)`, prints
  `UNPROVEN IN CI (accepted) — vitest` and `bin/gate locally, with npx convex dev running, is
the only proof of it`, then exits 0. Anything **other** than the Convex hole — a missing
  browser, a silent skip, a zero-test grep, a missing tool — emits `::error` and exits 2.
- **What it must never do, and does not:** set a placeholder `CONVEX_URL`. A dead port turns the
  auth tests into the permanent silent skip this whole gate exists to prevent.

## 3. What changed

`.github/workflows/ci.yml`

- Job `verify` → `gate`, `timeout-minutes: 15` → `30` (the gate is a superset: two builds, three
  Playwright runs).
- `bun run verify` + `test:e2e` + `test:dev` + `build && smoke-node` collapsed into one step:
  `bin/gate --ci`.
- Added an explicit "Verify dependencies are installed" step: the gate shells out to
  `node_modules/.bin` and does not install, so a missing binary must be named once, clearly,
  rather than surfacing as a confusing per-step failure.
- `bunx playwright install --with-deps chromium` kept, renamed "Install chromium".
- Failure artifacts widened to `test-results/` and `playwright-report/`.
- Every `uses:` SHA pin preserved.

`playwright.config.ts`

- `workers` added, env-overridable (`PLAYWRIGHT_WORKERS`, default `2`), with the measurement in
  a comment. CI and the gate now use the same number without either passing a flag.
- `webServer.timeout` made overridable (`PLAYWRIGHT_WEBSERVER_TIMEOUT`, default `300_000`).

`bin/gate`

- New steps: `secret-scan`, `version`, `svelte5-guard`, `assets`, `dev-smoke`, `node-smoke`.
- Browser suite now runs with `--reporter=list,json`; the JSON report is reduced to
  total/skipped/declared-reason/silent counts. Three new UNPROVEN causes: zero tests ran, a
  skipped test states no reason, the dev `--grep` matched nothing.
- Declared Playwright skips are printed with their reasons in the existing grouped skip section;
  they do not make the run UNPROVEN. Unexplained skips do.
- `--ci` mode: `::error`/`::warning` annotations and exactly one tolerated UNPROVEN (the vitest
  Convex hole, and only when every skip reason is a Convex one). Local `bin/gate` is unchanged:
  any UNPROVEN is still exit 2.
- Removed the `--workers` flag from the script now that the config owns it.

## 5. What a runner would have to prove

Nothing below can be established from this machine. Each line is a claim this document does
**not** make.

1. **The workflow is accepted by Actions at all.** No `actionlint` here. Unknown keys, a bad
   `needs`, or a malformed `${{ }}` would only appear on the first run.
2. **The action SHAs still resolve.** `actions/checkout@3d3c42…` (v7.0.1),
   `actions/setup-node@949feb…` (v7.1.0), `oven-sh/setup-bun@0c5077…` (v2.2.0),
   `actions/upload-artifact@cf430e…` (v7.0.2). Unchanged from the previous workflow, but not
   re-verified against GitHub.
3. **`setup-node` accepts `.node-version` containing a bare `22.23.2`.** It supports a version
   file in nvm format; a single bare version is the common case, but the pin is only proven here
   by reading it.
4. **`setup-bun` resolves `bun-version-file: package.json` to `1.4.2`.** Verified by reading the
   action's source (`packageManager?.split("bun@")[1] ?? engines?.bun`), not by running it.
5. **`bun install --frozen-lockfile` succeeds on a clean Linux runner** with Node 22 and Bun
   1.4.2. This checkout has a symlinked `node_modules` and Node 26, so the install path is
   genuinely unexercised.
6. **`bin/gate --ci` passes on `ubuntu-latest`.** Specifically: does the 4-vCPU runner at
   `workers: 2` reproduce the green suite? Does `webServer.timeout` hold on a cold filesystem?
   Does `chromium-1234` (this host's browser) match what `playwright install` fetches there?
7. **The elapsed time fits `timeout-minutes: 30`.** Locally the gate takes roughly 10 minutes
   warm with 16 cores; a 4-vCPU runner with a cold cache is plausibly 2–3× that. If the job
   times out, the timeout is the thing to raise — not the steps to remove.
8. **`bin/gate --ci` exits 0 with the Convex hole and exits 2 for every other UNPROVEN.** Proven
   locally only in the Convex-hole direction (this host has no deployment, so the local run is
   exit 2). The negative direction — CI failing on, say, a missing browser — was reasoned from
   the code, not observed.
9. **The `--ci` annotations render.** `::error`/`::warning` on stdout are interpreted by the
   runner. Not observed.
10. **The local/CI Node split does not bite.** CI is Node 22; this host is 26. Both run the unit
    suite, but only 22 can push Convex. If a future step needs the push, it must run on 22 and
    the difference has to be stated in the workflow.

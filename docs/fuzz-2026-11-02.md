# Fuzz pass — 2026-11-02

Property-based testing over every hand-written parser and validator in the tree. The point was to
find the inputs nobody thought of, not to re-assert the cases the unit tests already cover.

Everything here is deterministic: each generator is a seeded PRNG (`xorshift32`, no dependency, no
`Math.random`), so a failure reproduces on the exact same input by re-running the suite. No case in
this document was found by luck and then lost.

## Method

Assertions are properties, never golden outputs:

- a parser never throws on any input — it returns a value or a refusal;
- a refusal never carries a value;
- output length is bounded by the declared limit;
- no output contains a control character the input did not contain;
- `safeLink` never returns an href whose host differs from what a reader would see;
- a decoder never returns more bytes than the declared cap;
- a graph walk on a cyclic graph terminates;
- a policy lookup that finds no entry denies.

Iteration counts are per property, chosen to keep the whole suite inside the gate's budget rather
than to look thorough.

## The three real failures

### 1. Prototype inheritance admitted a policy verb (`src/lib/server/policy.ts`)

```ts
const candidate = entries[verb]; // before
```

An object passed with an inherited `exec` — `Object.create({ exec: 'allow' })`, or anything
deserialised onto a prototype — was read as a policy. `entries[verb]` does not distinguish an own
property from an inherited one, so "missing entry" did not reliably mean deny.

Fixed with `Object.hasOwn(entries, verb) ? entries[verb] : undefined`. This is the one finding in
this pass with a security shape rather than a cosmetic one: the deny-by-default rule was only
true for plain objects.

### 2. Composer selection index went out of range (`src/lib/composer_commands.ts`)

```ts
if (!count) return -1;
if (key === 'ArrowDown') return (current + 1 + count) % count; // before
```

`count` comes from a derived array length, but a negative or fractional value indexed outside the
list: `(-5 + 1 + -1) % -1` returned `-0`, and the `Enter` path returned `-2`. `-1` is the caller's
"nothing selected" sentinel, so any other negative value pointed at no row while looking like a
selection.

Fixed by refusing a non-integer or non-positive `count` and normalising `current` with
`((current % count) + count) % count`. Minimised input: `nextComposerSelection('Enter', -5, -1)`.

### 3. Workflow edge derivation was quadratic (`src/lib/workflow_graph.ts`)

```ts
.filter((edge) => edge.to === 'end' || steps.some((step) => step.id === edge.to));  // before
```

`steps.some` inside a filter over edges. A 20 000-step spec took **1.3 s of blocking main-thread
work**, and the canvas re-derives this on every edit. Not a correctness bug — a stall that only
appears on a large workflow, which is exactly the case a small test never reaches.

Fixed with a `Set` of ids built once. Same output, linear.

## What was deliberately not changed

- No property was weakened to make a failure disappear. Each of the three above is fixed at the
  source and pinned by a named regression case.
- No generator was narrowed to avoid a region. Where a property is expensive, the iteration count
  was lowered, not the property.

## Cost

The suite runs in the gate. It is deterministic, seeds are fixed, and no case depends on wall-clock
time or on the host's CPU count.

## How the numbers were produced

`@vitest/coverage-v8` is **not** in `node_modules` (only `vitest` 4.1.11 is), and installing was
out of scope. It is present in the bun cache, so it was loaded through Vitest's
`customProviderModule` with a throwaway resolution directory. Nothing was added to the repo or to
`package.json`; the temporary config was deleted before commit.

One-off measurement script (kept out of the commit):

```bash
# 1. throwaway provider directory (bun cache -> /tmp, no install)
#    @vitest/coverage-v8@4.1.12 + its transitive deps, copied from ~/.bun/install/cache
# 2. temporary config at the repo root that merges vite.config.ts and adds:
#      test.coverage = {
#        provider: 'custom',
#        customProviderModule: '/tmp/opencode/covmod/node_modules/@vitest/coverage-v8/dist/index.js',
#        reporter: ['json-summary','json'],
#        reportsDirectory: process.env.COV_OUT,
#        include: ['src/**/*.{ts,js}'],
#        exclude: ['src/convex/_generated/**','**/*.d.ts','**/*.test.ts','**/*.spec.ts']
#      }
# 3. run it
COV_OUT=/tmp/opencode/cov-after npx vitest run --config cov.tmp.config.mts --coverage --testTimeout=180000
```

`--testTimeout=180000` is needed **only** under instrumentation.
`src/lib/config/linting.spec.ts` boots a full typed-ESLint project service; with v8 coverage
attached it exceeds the project's 30 s `testTimeout`. It passes normally in ~2 s. This is a
measurement-tooling artefact, not a product or test defect.

The command for ordinary verification (no coverage plugin needed) is unchanged:

```bash
npx vitest run
```

clicking such a link is still shown the href text by the renderer.

## Corrections made to my own tests (code untouched)

Three of my first attempts asserted something the code does not do. In each case the code's
behaviour is defensible, so the test was corrected:

1. `safeLink` **does** allow `user:pass@` userinfo. Rewritten as a documented finding about which
   host a browser will contact, instead of an assertion that it is rejected.
2. A remote MCP `isError: true` is returned **as data** (`{content, isError}`), not thrown. The
   thrown-error branch (with the "may have completed remotely" warning) is a transport failure;
   both paths are now tested separately.
3. `parseMarkdown('--- x')` is a paragraph, not a list or a rule — the rule pattern is anchored to
   the whole line. Assertion corrected.

Also fixed two harness bugs of mine rather than product bugs: `consumeBurst` is keyed per token and
lives for a minute, so each route test now uses a fresh token; and `clearAllMocks` does not drain
queued `mockReturnValueOnce` values, so the tool-loop tests call `mockReset()` per test.
